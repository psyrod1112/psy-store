## 프로젝트 설명
 **"내가 앞으로 1일 1프로젝트 하면서 만들앱들을 구매할 수 있는 플랫폼**
 구체적 설명 : 앞으로 나의 1일 1프로젝트를 타인이 주문, 이용할 수 있는 플랫폼


## MVP IN
- 회원: 이메일/비밀번호 가입과 로그인 (Spring Security + JWT)
- 카탈로그: 앱 목록과 상세 (제목, 설명, 가격, 스크린샷 1장)
- 앱 등록: 판매자는 나 하나(ADMIN 권한). 다중 판매자는 받지 않음
- 구매: 주문 생성 → 토스페이먼츠 테스트키 결제 승인 → 소유권 부여
- 내 라이브러리 + 다운로드: 소유한 앱만, 짧게 만료되는 서명 URL로 다운로드

## MVP OUT
- 추천, 리뷰/평점 시스템
- 장바구니 및 위시리스트
- 다중 판매자(판매자 등록 시스템)
- 환불, 할인 및 쿠폰 시스템
- 검색 시스템
_v2 로드맵_

## 도메인 모델
- 소유권과 주문 분리 WHY? 주문은 이력일 뿐이고, 다운로드 시 소유권만 확인하게 됨.
- 주문에는 가격을 스냅샷(그때 기록)으로 저장
- 정합성 WHY? 주문을 했는데 소유권 X / 주문이 안됐는데 소유권 O 등의 예외상황 차단.
- 멱등성 WHY? 주문을 2번눌러 2번주문 등의 예외상황 차단.

## 기술 결정
- 구조 : 모듈러 모놀리스 (기능별 수정, 추가 사항을 반영하기 용이)
- 언어/프레임워크 : JAVA/Spring Boot, Gradle(Kotlin DSL)
- DB : Postgres (이미 있는 인프라 재사용)
- Redis : 사용 X (현재 MVP단계에서는 불필요, 랭킹/추천 시스템 도입 시 사용 예정)
- 파일 저장소 : Cloudflare R2 (이미 있는 인프라 재사용)
- 결제 : 토스 Payment (사업자등록이 필요해서 토스를 골랐음)
- 프론트 : 최소한의 기능만 하도록 (백엔드가 이 프로젝트 메인)
- 앱 형태: 다운로드형 (접근권형은 v2)

```
dev.psyrod.store
├── member     회원/인증
├── catalog    앱·릴리스
├── order      주문
├── payment    결제 (PaymentGateway 인터페이스 + 토스 구현)
├── library    소유권·다운로드
└── common     에러 응답, 공통 설정
```
